Phishing Cognitive Bias Detection – BPRSM Artefact
This repository contains the implementation of the Bias‑Based Phishing Risk Scoring Model (BPRSM) developed as part of a Masters project at the University of the West of England (UWE). The artefact provides a computational framework to analyse email texts, extract cognitive bias indicators (Authority, Urgency, Fear, Elicitation), and produce a Holistic Risk Index (HRI) with explainable forensic narratives.

🚀 Getting Started
Prerequisites
Python 3.8 or later

Required Python packages: pandas, numpy, scikit‑learn, matplotlib, seaborn, beautifulsoup4, email, re, tarfile, json

Install all dependencies with:

bash
pip install pandas numpy scikit-learn matplotlib seaborn beautifulsoup4
(Standard library modules email, re, tarfile, json are already included with Python.)

🧪 Running the Analysis Pipeline
The pipeline consists of two sequential steps:

1. Preprocess the corpus – process_emails.py
This script:

Reads all .tar.bz2 archives in the repository root.

Extracts the raw email messages from each archive.

Parses the email headers and body, discarding attachments.

Saves a consolidated DataFrame (as a pickle file) with columns: filename, label (ham/spam), subject, body, and full_text.

Run it:

bash
python process_emails.py
Expected output:
A file email_data.pkl will be created in the current directory. This file is used by the next script.

2. Run the comprehensive analysis – comprehensive_analysis.py
This script performs the core BPRSM analysis:

Load email_data.pkl.

Parse each email body to count occurrences of predefined keywords for four bias categories: Authority, Urgency, Fear, and Elicitation (using a fuzzy‑matching regex to handle character‑level obfuscation).

Compute features: individual bias hit counts, total trigger density, and the synergy bonus (if both Authority and Urgency are present).

Train a Random Forest classifier (100 trees) on an 80/20 stratified split.

Evaluate and output:

Classification report (precision, recall, F1, accuracy)

ROC‑AUC score

Confusion matrix plot

Feature importance bar chart

Violin plot of trigger density by class

Co‑occurrence frequency matrix (heatmap)

Correlation matrix (heatmap) for bias pairs

Save the dashboard data as dashboard_data.json (used by the HTML dashboard).

Run it:

bash
python comprehensive_analysis.py
Expected outputs:

Terminal print of the classification report, ROC‑AUC, and feature importances.

Five PNG files in the repository root:

confusion_matrix.png

feature_importance.png

trigger_density.png

synergy_matrix.png

synergy_co_occurrence.png

A JSON file dashboard_data.json containing the processed data for the frontend.

🖥️ Using the Cognitive Research Dashboard
The dashboard is a self‑contained HTML page that visualises the risk scoring model in action. It can be used both to explore the pre‑computed results and to analyse your own email text.

Open the Dashboard
Simply open new risk_dashboard.html in any modern web browser:

bash
# On macOS
open new\ risk_dashboard.html

# On Windows
start new\ risk_dashboard.html

# On Linux
xdg-open new\ risk_dashboard.html
Dashboard Features
Holistic Risk Index (HRI) – A numeric score (0‑30+) with a colour‑coded gauge indicating Low, Moderate, or Critical risk.

Pathological Profile – Bar chart showing the hit counts for each of the four bias categories.

Forensic Narrative – A textual explanation of why the email was flagged, linking detected triggers to known social engineering techniques (e.g., “Institutional Mimicry”, “Crisis‑Driven Semantic Framing”).

Synergy Indicator – Highlights when both Authority and Urgency are present and applies the synergy bonus.

Paste‑and‑analyse – You can paste any email text into the text area and click “Analyse” to get an instant risk assessment (the dashboard uses the same keyword‑based parser as the Python scripts).

Note: The dashboard loads the pre‑computed dashboard_data.json (generated by comprehensive_analysis.py) to display summary statistics and sample emails. If you have not run the analysis, the dashboard will still work for ad‑hoc text analysis, but the sample data section will be empty.

🔧 Customisation and Extending
Adding new keywords: Edit the keyword lists inside comprehensive_analysis.py (the dictionaries authority_keywords, urgency_keywords, etc.).

Adjusting synergy weight: Change the SYNERGY_BONUS variable in comprehensive_analysis.py (default 2.5).

Changing risk thresholds: Modify the THRESHOLD_LOW and THRESHOLD_HIGH constants in the Python script (also mirrored in the dashboard’s JavaScript).

📝 Notes
The corpus used is the SpamAssassin Public Corpus (2002‑2005). While it is a classic benchmark, it may not reflect modern phishing tactics. The model’s feature set is, however, calibrated against newer datasets (CSAW‑MDD, SignalSpam) as described in the research write‑up.

The dashboard’s analysis is performed client‑side – no data is sent to any server.

For a full understanding of the theoretical background, methodology, and discussion, please refer to Risk Mails.docx.
